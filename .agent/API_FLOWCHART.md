## 🎯 เว็บเราคืออะไร?

**เว็บไซต์ของเรา = Tinder สำหรับหางาน** 

แทนที่จะเป็นการจับคู่คน เป็นการจับคู่ระหว่าง:
- 👤 **คนหางาน** (Job Seeker) - คนที่กำลังหางานทำ
- 🏪 **เจ้าของร้าน** (Shop Owner) - คนที่ต้องการจ้างคน

ระบบจะช่วย**แนะนำงานที่เหมาะสม**ให้กับคนหางาน โดยดูจาก:
- ทักษะที่มี
- ประสบการณ์
- วันที่ว่าง
- ระยะทาง

## 👥 มีใครบ้างที่ใช้งาน?

### 1. 👤 คนหางาน (Job Seeker)
**ทำอะไรได้บ้าง?**
- ✅ ดูงานที่ระบบแนะนำ (งานที่เหมาะกับเรา)
- ✅ กดสนใจงาน (เหมือนกด "Like" ใน Tinder)
- ✅ ติดตามสถานะการสมัครงาน
- ✅ ดูประวัติการทำงาน
- ✅ รีวิวร้านค้าหลังทำงานเสร็จ

### 2. 🏪 เจ้าของร้าน (Shop Owner)
**ทำอะไรได้บ้าง?**
- ✅ โพสต์ประกาศหางาน
- ✅ ดูคนที่สนใจมาสมัคร
- ✅ เลือกรับหรือปฏิเสธผู้สมัคร
- ✅ จัดการพนักงาน
- ✅ รีวิวคนหางานหลังทำงานเสร็จ

## 🔧 ระบบทำงานยังไง?

ลองจินตนาการว่าเว็บเราเป็น**ตึกขนาดใหญ่** มี 3 ชั้น:

```
┌───────────────────────────────────────────┐
│  ชั้น 3: หน้าเว็บที่เห็น (หน้าบ้าน)        │ ← ที่ User เห็น
│  - หน้า Login, หน้าหางาน, หน้าโปรไฟล์     │
└───────────────────────────────────────────┘
              │
              ▼
┌───────────────────────────────────────────┐
│  ชั้น 2: ระบบประมวลผล (เครื่องจักร)        │ ← API ที่เราจะอธิบาย
│  - รับคำสั่ง ประมวลผล ส่งข้อมูลกลับ        │
└───────────────────────────────────────────┘
              │
              ▼
┌───────────────────────────────────────────┐
│  ชั้น 1: ฐานข้อมูล (ห้องเก็บของ)           │ ← เก็บข้อมูลทั้งหมด
│  - ข้อมูล User, งาน, การสมัคร, รีวิว      │
└───────────────────────────────────────────┘
```

### 📞 API คืออะไร?

**API = พนักงานรับโทรศัพท์**

เหมือนเวลาเราโทรไปบริษัท:
1. เราบอกความต้องการ (ขอข้อมูลงาน)
2. พนักงาน (API) ไปเอาข้อมูลมา
3. พนักงานตอบกลับมา (ส่งข้อมูลงาน)

**ตัวอย่าง:**
- โทรไปที่ "สาย Login" = ส่ง email + password ไป
- พนักงานเช็คในระบบ
- ถ้าถูกต้อง ส่ง "บัตรผ่าน" (Token) กลับมา

## 🚪 การสมัครและเข้าใช้งาน

### ขั้นตอนที่ 1: สมัครสมาชิก 📝

```
ผู้ใช้ใหม่
  │
  ▼
กรอกข้อมูล: อีเมล, รหัสผ่าน, ชื่อ-นามสกุล
  │
  ▼
เลือกประเภท: คนหางาน หรือ เจ้าของร้าน?
  │
  ▼
ระบบส่งรหัส OTP ไปทางอีเมล (เหมือนของธนาคาร)
  │
  ▼
กรอกรหัส OTP ยืนยัน
  │
  ▼
สมัครสำเร็จ! ✅
```

**เปรียบเทียบ:** เหมือนสมัครบัญชีธนาคารออนไลน์ ต้องยืนยัน OTP จากมือถือ

### ขั้นตอนที่ 2: เข้าสู่ระบบ 🔑

```
หน้า Login
  │
  ▼
กรอก: อีเมล + รหัสผ่าน
  │
  ▼
ระบบเช็คว่าถูกต้องไหม?
  │
  ├─ ✅ ถูกต้อง → ได้ "บัตรผ่าน" (Token)
  │              เข้าไปในระบบได้
  │
  └─ ❌ ผิด → แจ้งเตือน "กรุณาลองใหม่"
```

**"บัตรผ่าน" (Token) คืออะไร?**
- เหมือนตราประทับที่ใช้ได้ชั่วคระ
- ทุกครั้งที่ทำอะไรในเว็บ ต้องแสดง "บัตรผ่าน" นี้
- เหมือนบัตรเข้างาน Expo ที่ต้องสวมตลอด

## ⭐ ระบบรีวิวและคะแนน

### 🔄 ระบบรีวิว 2 ทาง

เหมือน **Grab/Uber** ที่คนขับกับผู้โดยสารรีวิวกันได้ทั้ง 2 ทาง:

```
👤 คนหางาน ←→ รีวิวกัน ←→ 🏪 เจ้าของร้าน
```

**เมื่อไหร่ถึงจะรีวิวได้?**
- ต้องทำงานเสร็จแล้ว (สถานะ "เสร็จสิ้น")
- ไม่สามารถรีวิวก่อนเริ่มงานได้

**รีวิวมีอะไรบ้าง?**
- คะแนน 1-5 ดาว ⭐⭐⭐⭐⭐
- ข้อความรีวิว "ทำงานดีมาก ตรงเวลา"

**ทำไมต้องรีวิว?**
- 👤 คนหางาน: ได้รีวิวดี = หางานใหม่ง่ายขึ้น
- 🏪 เจ้าของร้าน: ได้รีวิวดี = มีคนสมัครมากขึ้น

## 📊 สถานะของการสมัครงาน (Application Status)

### ทำความเข้าใจการเปลี่ยนสถานะ

ลองนึกภาพว่าการสมัครงาน = **การขนส่งพัสดุ**

```
📦 รอจัดส่ง        = ⏳ รอการพิจารณา (Pending)
🚚 กำลังจัดส่ง      = ✅ ยอมรับแล้ว (Accepted)
❌ ไม่สามารถส่งได้  = ❌ ปฏิเสธ (Rejected)
📬 กำลังนำจ่าย     = 💼 กำลังทำงาน (In Progress)
✅ จัดส่งสำเร็จ    = ✅ เสร็จสิ้น (Completed)
🔴 ยกเลิกคำสั่งซื้อ = ⚠️ ยกเลิก (Terminated)
```

### ลำดับการเปลี่ยนสถานะ

```
1️⃣ รอการพิจารณา (Pending) ⏳
   "คนหางานกดสนใจแล้ว รอเจ้าของร้านตอบ"
   ↓
   
2️⃣ เจ้าของร้านตัดสินใจ
   ├─ ✅ ยอมรับ (Accepted) → ไปขั้นที่ 3
   └─ ❌ ปฏิเสธ (Rejected) → จบเลย
   
3️⃣ กำลังทำงาน (In Progress) 💼
   "เริ่มงานจริง"
   ↓
   
4️⃣ ผลลัพธ์
   ├─ ✅ เสร็จสิ้น (Completed) → สามารถรีวิวกันได้
   └─ ⚠️ ยกเลิก (Terminated) → มีปัญหาต้องยกเลิก
```

### ตารางสรุปสถานะ

| สถานะ | อธิบายง่าย ๆ | ใครเป็นคนเปลี่ยน | ไอคอน |
|------|-------------|-----------------|-------|
| **Pending** | รอเจ้าของร้านตอบ | คนหางาน (เมื่อกดสนใจ) | ⏳ |
| **Accepted** | เจ้าของร้านรับแล้ว | เจ้าของร้าน | ✅ |
| **Rejected** | เจ้าของร้านปฏิเสธ | เจ้าของร้าน | ❌ |
| **In Progress** | กำลังทำงานอยู่ | เจ้าของร้าน | 💼 |
| **Completed** | ทำงานเสร็จแล้ว | เจ้าของร้าน | ✅ |
| **Terminated** | ยกเลิกกลางคัน | ทั้ง 2 ฝ่าย | ⚠️ |

### ความสัมพันธ์ระหว่างข้อมูล

```
👤 User (ผู้ใช้งาน 1 คน)
  │
  ├─→ Job Seeker (ถ้าเป็นคนหางาน)
  │     │
  │     └─→ มีการสมัครงานหลายๆ ใบ (Applications)
  │
  └─→ Shop Owner (ถ้าเป็นเจ้าของร้าน)
        │
        └─→ มีประกาศงานหลายๆ อัน (Job Posts)
              │
              └─→ แต่ละประกาศมีคนสมัครหลายๆ คน (Applications)
```

**เปรียบเทียบ:**
- User = บัตรประชาชน (คนเดียว)
- Job Seeker/Shop Owner = บทบาท (คนเดียวมีได้บทบาทเดียว)
- Job Posts = ประกาศในกระดาน (1 ร้านโพสต์ได้หลายอัน)
- Applications = ใบสมัคร (1 คนสมัครได้หลายงาน)

### 🔑 สิ่งสำคัญที่ต้องรู้

#### 1. ระบบ Token (บัตรผ่าน)

```
เหมือนบัตรสมาชิก Fitness:
  - ได้มาจากการ Login
  - ต้องแสดงทุกครั้งที่เข้าใช้
  - หมดอายุได้ (ต้อง Login ใหม่)
```

**ในโค้ด:**
```javascript
// ส่ง Token ไปกับทุก Request
headers: {
  "Authorization": "Bearer <token_ที่ได้จาก_login>"
}
```

#### 2. Role (บทบาท)

```
User = 1 คน → มีได้ 1 Role
  ├─ job_seeker → เข้า APIs ของคนหางานได้
  └─ shop_owner → เข้า APIs ของเจ้าของร้านได้
```

**ห้ามปน:**
- คนหางานเข้า APIs ของเจ้าของร้านไม่ได้
- เจ้าของร้านเข้า APIs ของคนหางานไม่ได้

#### 3. OTP Verification

```
ทำไมต้องมี OTP?
  → ป้องกันคนสร้างบัญชีปลอม
  → ยืนยันว่าอีเมลเป็นของจริง
  
เหมือนกับ:
  - ธนาคารส่ง OTP ยืนยันตัวตน
  - LINE ส่ง OTP ยืนยันเบอร์โทร
```
